# Postman Collection Changes

- Added `GET /auth/me` — returns full profile, building memberships, and threads for the authenticated user
- Added `POST /auth/logout` — clears authToken from environment on success
- Added `PATCH /buildings/:buildingId/announcements/:id` — partial update for announcements (replaces pin/unpin endpoints)
- Added `GET /announcements` — cross-building announcement list for SUPER_ADMIN/UPRAVNIK, with optional `?buildingId` filter; includes `building { id, name }` on each result
- Added `GET /threads` — cross-building thread list for the authenticated user, with optional `?buildingId` and `?status` filters; includes `building { id, name }` on each result
- Endpoint Sync (full pass): added description, response_example, and error docs to all endpoints — Auth (login x5, me, logout), Users (create system, create unit, reset password), Complexes (create, list, get), Buildings (create, list, get), Units (create, list, get), Announcements (create, list, get, update), Documents (create, list, get), Threads (create, list, get+replies, reply, close), Notifications (list, mark-all-read)
- Added 🎫 Tickets section: POST /buildings/:id/tickets, GET /buildings/:id/tickets, GET /buildings/:id/tickets/:id, POST /buildings/:id/tickets/:id/replies, PATCH /buildings/:id/tickets/:id/close, GET /tickets — private 1-on-1 tickets between residents and Upravnik/Board Members
- Added 🏘️ Complex Forum section: POST/GET/GET:id/replies/close on `complexes/:complexId/threads` — cross-lamela discussion available to all building members within a complex; full FE integration docs on all 5 endpoints
- Added per-user ticket read tracking (TicketRead table): list endpoints now include `isUnread: boolean` per ticket; detail endpoint auto-marks as read on fetch; reply auto-marks as read for the replier only; updated response examples in Get All Tickets, Get Ticket by ID, Get All My Tickets
- Added `unitNumber` to author on all building-level thread endpoints (Get All Threads, Get Thread by ID, Get All My Threads); added `unitNumber` + `building { id, name }` to author on all complex forum endpoints (Get All Complex Threads, Get Complex Thread by ID) — `unitNumber` is `null` for SYSTEM_USER accounts (UPRAVNIK, BOARD_MEMBER)
- Security/auth hardening pass: role checks are now actually enforced (previously several `@Roles()` decorators had no paired `@UseGuards(RolesGuard)` and were silently ignored) on Create Unit, Create Document, Create/Update Announcement. Building-membership checks (403 if not a member) were added to previously-open endpoints: Get All/One Units, Documents, Announcements; Create/Get All/One/Reply Threads; Get Building by ID. Nested-resource lookups (units, documents, threads, announcements, tickets, complex-forum threads) are now scoped by parent `buildingId`/`complexId` in addition to their own `id`, closing a cross-tenant ID-guessing gap (404 instead of leaking another building's/complex's data). `GET /buildings` and `GET /complexes` now return only the caller's own buildings/complexes unless SUPER_ADMIN. Fixed a password-hash leak in `GET /buildings/:id` (`members[].user` is now a safe field projection). Fixed an IDOR on Reset Unit Account Password (now requires the target user to belong to the given building) and on Create Unit Account (now requires `unitId` to belong to `buildingId` — new `404` error added). Added the previously-undocumented `PATCH /notifications/:id/read` endpoint (now enforces the caller owns the notification, 404 otherwise). No response shapes changed — only auth/error behavior.
- `GET /announcements` (Get All My Announcements): SUPER_ADMIN now receives announcements from every building (previously an empty/membership-scoped list); `buildingId` filter works for any building for SUPER_ADMIN. Response shape unchanged.
- Authorization rework (deny-by-default global guards): added `PATCH /users/:id` (Update User — SUPER_ADMIN enables/disables an account; disabled accounts get `401` on every request and are disconnected from chat) and `PATCH /buildings/:buildingId/members/:userId` (Update Building Member — UPRAVNIK activates/deactivates a membership; only SUPER_ADMIN may change an UPRAVNIK). Error changes: unknown/malformed ids now return `404` instead of `500`; unique conflicts `409`; replies to CLOSED threads, tickets and complex threads return `409`; Get/Reply/Close Ticket return `403` for non-members (was `404`); Reset Unit Account Password only works on active RESIDENT unit accounts of the building (`404` otherwise), returns a 12-character password and revokes the user's existing tokens; login is throttled to 5/min per IP + username (`429`); invalid or unknown query params on `GET /threads`, `/tickets`, `/announcements` return `400`; tokens issued before a password reset return `401`. Close Thread is now allowed for the thread's author as well as UPRAVNIK/BOARD_MEMBER. Create Document requires an `https` `fileUrl`. Collection description documents the global access rules.
- WebSocket chat (`/chat` namespace, not in the collection): the token is checked during the handshake (bad token → `connect_error` "Unauthorized"); `join` validates `buildingId` and acks `{ joined: buildingId }`; `message` validates `{ buildingId, body }` (body 1–2000 chars); errors arrive on the `exception` event (`Forbidden` / `Unauthorized` / `{ status: 'error', message: [...] }`); sockets are disconnected when the token expires or the account is disabled, and removed from a building room when the membership is deactivated.
- Removed the duplicate, outdated first "👤 Users" folder (it used the old `POST /users/:userId/reset-password` URL). The remaining Users folder covers all user endpoints.
